# Этап 3 — первая синхронизация подтверждена владельцем

Дата: 03.11.2026. Настройка не требует secret/service_role или пароля базы.
Системные файлы и настройки ОС не менялись; все новые файлы внутри проекта.

## Реализовано

- Supabase Auth с хранением токенов в отдельном IndexedDB; пароль не записывается.
- Первая явная привязка местной истории к разрешённому Auth-аккаунту, резервный
  снимок до привязки, сохранение UUID/результатов/времени. Повторный вход тем же
  владельцем не требует повторной передачи прав и не меняет историю.
- Запрет смешения аккаунтов и закрытие UI с банком/историей после выхода.
- Закрытый bank_source, проверка хеша JSON/PNG и загрузка на новое устройство.
  Начальная установка банка от allowlisted владельца; посторонний не может
  включить себя в список доступа, загрузить банк, прочитать историю или картинки.
- Outbox в той же транзакции, что попытка и позиция. Идемпотентные повторы,
  восстановление после потери ответа сервера, объединение обеих офлайн-попыток.
- CAS для сессий/отметок/темы/активной тренировки. Обе версии сохраняются в конфликте;
  выбор явный, история ответов не участвует в перезаписи. Есть «Продолжить здесь».
- Индикатор синхронизации, ручной повтор, периодическая отправка и реакция на сеть.

## Что сделано в настоящем Supabase

Миграции 0001/0002 применены из private/setup-supabase.sql. Результат SQL Editor:
trainer_cloud_ready, allowed_users=1. Включён RLS, anon лишён прав чтения на всех
13 API-таблицах, Storage question-images приватный. Самостоятельная регистрация
выключена; анонимный вход и ручное связывание идентичностей остаются выключенными,
подтверждение email включено. Изменения Auth воспроизводятся по SUPABASE_SETUP.md.

HTTP-запросы к настоящему API без входа отклонены на всех 13 таблицах: 401/42501.
SQL-проверка с ролью authenticated и UUID не-члена вернула 0 записей; отдельно
проверены метаданные RLS/GRANT. Это не HTTP-вход настоящего второго аккаунта.
Снимки SQL/настроек и отчёт API сохраняются в reports/, исключённой из git.

## Проверки реализации

typecheck, lint, unit/integration, E2E и build запускаются перед сдачей. Тесты:
- обновление IndexedDB v1 → v2 без сброса;
- привязка владельца, сохранение UUID и отказ другому аккаунту;
- повторная отправка после потери ответа, изменения во время отправки;
- независимые ответы двух офлайн-устройств и пересчёт проблемного состояния;
- обе конфликтующие позиции, явный выбор и версия устройства;
- доступ anon/не-члена, приватный Storage, неизменяемые ключи;
- полный браузерный поток Auth/переноса/двух устройств/выхода/другого аккаунта
  на синтетическом API с настоящим Supabase SDK.

## Ограничения до приёмки

Владелец должен войти через «Подключить облако» в привычном браузере, подтвердить
первую привязку и дождаться «Синхронизировано». До этого нельзя сообщать, что его
реальный вопросник или история уже загружены в облако. Пароль вводится только
в приложении. Физические Windows/Android/Linux ещё не проверены, HTTPS-размещения
нет. PWA, пробный экзамен и экспорт/импорт резервных копий — этап 4.
