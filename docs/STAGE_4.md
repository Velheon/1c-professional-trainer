# Этап 4 — PWA, экзамен и резервные копии

03.11.2026. Реализованы код и локальная сборка. Размещение на HTTPS и приёмка
на физических Windows/Linux/Android ещё не выполнены: у владельца пока нет аккаунта хостинга.
Новые SQL-миграции не нужны: экзамен хранится в существующем версионируемом
снимке сессии, результаты — в immutable attempts с mode=exam.

## Резервная копия

На главной откройте «Резервная копия истории» → «Скачать историю JSON».
Скопируйте файл в своё надёжное хранилище. Он содержит личную историю,
сессии, отметки и тему; вопросы, изображения, Auth-токены, ключи и пароли исключены.

Для восстановления сначала загрузите тот же банк (из облака или своего ZIP),
затем выберите JSON. До записи показаны новые/существующие попытки и различия
сессий/отметок. По умолчанию текущие сессии, отметки и тема сохраняются;
можно явно выбрать восстановление из копии. Попытки объединяются при любом выборе.
Импортированные сессии продолжаются через «Сохранённые тренировки»;
активная сессия автоматически не переключается. Завершённый экзамен не
открывается заново при восстановлении более ранней копии. Исходные изменяемые данные
перед восстановлением сохраняются дополнительным снимком в IndexedDB.

Формат: `format=1c-trainer-history`, `version=1`. Дедупликация по UUID;
разное содержимое immutable записи с тем же UUID отменяет всю транзакцию.
Перед записью повторно проверяются владелец, банк, ключи и ссылки.
Повторный импорт не удаляет и не дублирует попытки. Новые события попадают
в обычную очередь синхронизации; её конфликты разрешаются существующим интерфейсом.

В привязанном браузере допускается копия того же облачного владельца и проекта.
Пустой непривязанный браузер может принять локальный профиль копии, сохраняя
собственный device_id. История двух разных локальных профилей не смешивается
молча: сначала привяжите оба к своему облачному аккаунту. Старую копию,
сделанную до облачной привязки, восстанавливайте в пустом локальном браузере,
затем привязывайте его к своему аккаунту с подтверждением переноса.
Копия не даёт права доступа к платному банку и не заменяет авторизацию на сайте.

## Пробный экзамен

Главная → «Начать пробный экзамен». 14 уникальных вопросов: для исходного
14-раздельного банка по одному из каждого раздела, затем перемешиваются вопросы.
Ответы сохраняют исходный порядок. Это учебная модель выбора, не известный
алгоритм официального экзамена. Формат 14/30/12 сверён с
[правилами 1С](https://1c.ru/prof/exam.htm).

Выбор сохраняется локально, его можно менять. Ключи, пояснения и ChatGPT до
завершения скрыты. Срок окончания хранится в UTC, таймер идёт при закрытой
странице; при следующем открытии просроченный экзамен завершается. Закрытие
или выход на главную не останавливает таймер. «Завершить экзамен» требует
явного подтверждения; истечение времени завершает автоматически.

После завершения записывается по одной попытке для каждого отвеченного вопроса.
Неотвеченные учитываются в экзаменационном результате, но попытку не создают.
Порог сдачи — 12. Отчёт открывает правильные варианты, выбор, исходные пояснения,
изображения и ссылки. Результаты доступны на главной отдельно; не влияют
на охват и повторения. Повторная финализация не добавляет попыток.
Таймер опирается на часы устройства: это личный тренажёр без серверного прокторинга.

## PWA и офлайн

Manifest, PNG-иконки 192/512, maskable-иконка, service worker и кеш оболочки
создаются в production-сборке. В dev service worker не регистрируется.
Кешируется только фиксированный список ассетов сборки; запросы Supabase,
Auth и приватный контент в Cache Storage не попадают. Банк, все PNG и история
остаются в IndexedDB после их успешной загрузки.

Обновление устанавливается в ожидание: кнопка «Обновить приложение»
перезагружает страницу по вашему действию. Без нажатия новая версия активируется
после закрытия прежних вкладок. База не очищается. Предыдущий кеш оболочки
сохраняется для уже открытых вкладок; неуспешная установка удаляет неполный кеш.

После первого входа и загрузки банка можно запустить сайт без сети,
выбрать «Продолжить офлайн на этом устройстве», решать и закрывать его.
При возвращении сети проверка членства повторяется и очередь синхронизируется.
Выход из аккаунта закрывает офлайн-вход, сохраняя данные для того же владельца.
Кнопка запроса постоянного хранения снижает риск автоматического удаления
браузером, но не защищает от ручной очистки; JSON-копии остаются необходимыми.

Локальная проверка сборки:

```sh
npm run build
npm run check:build
npm run preview
```

Адрес preview имеет отдельное хранилище относительно dev: войдите в облако
или перенесите историю через JSON. Существующий dev-сервер останавливать не нужно.
На телефоне установка требует размещённого HTTPS-адреса; localhost телефона
не открывает сервер ноутбука. Инструкция: [размещение](DEPLOYMENT.md).

## Проверка и границы

- Typecheck, ESLint, 44 unit/integration теста; отдельные проверки восстановления,
  порога 11/12, дедлайна, неизменяемости и повторного завершения.
- E2E: настоящий архив, клавиатура и мобильные размеры, JSON preview/cancel/merge,
  экзамен и перезапуск таймера; production PWA с настоящими PNG офлайн;
  облачный сценарий на синтетическом API без обращения к аккаунту владельца.
- В production PWA проверены офлайн-перезапуск, очередь, возврат сети, отсутствие
  API в Cache Storage и запрет офлайн-входа после выхода из аккаунта.
- Сборка проверяется на 5 104 приватных UUID, secret/service_role и тестовые ключи.
- Реальные Android/Windows, установка через системный диалог браузера, HTTPS
  заголовки хостинга и обновление между двумя опубликованными версиями требуют
  проверки после размещения. Автоматизированные мобильные размеры не заменяют
  физическую приёмку. Этап не объявляется полностью принятым до этой проверки.
- Vite предупреждает о главном JS-чанке >500 kB (примерно 212 kB gzip).
  Это ограничение размера загрузки; сборка завершается успешно.
