## Что сделать сейчас

1. В том браузере и по тому адресу, где уже учились, обновите тренажёр.
   Если кнопки подключения нет, перезапустите `npm run dev`: параметры окружения
   Vite подхватываются при запуске.
2. Нажмите **«Подключить облако»** в шапке. Введите email и пароль созданного
   Auth-пользователя. Это пароль аккаунта тренажёра, а не пароль базы или Dashboard.
   В чат пароль не отправляйте.
3. Подтвердите привязку местной истории и нажмите **«Подключить облако»** в форме.
   Этот выбор нужен только при первой привязке браузера. UUID попыток, ответы,
   результаты и время сохраняются; технический локальный владелец заменяется
   на Auth UUID. Исходный снимок истории сохраняется в IndexedDB перед переносом.
4. Дождитесь статуса **«Синхронизировано»**. При первом подключении локальный банк
   и PNG отправятся в закрытый Supabase; на новом устройстве они загрузятся оттуда.
   Вопросы и история не отправляются в сторонние ИИ или телеметрию.
5. При сетевой ошибке ответы остаются локально. Нажмите ↻ либо дождитесь сети.
   При конфликте показаны обе версии позиции/отметок: выберите нужную. История
   ответов обеих сторон остаётся; снимок разрешённого конфликта также сохраняется.
6. На другом устройстве откройте тот же развёрнутый сайт и войдите тем же аккаунтом.
   Для чужой активной сессии нажмите **«Продолжить здесь»**. HTTPS-сайт
   пока не размещён: локальный адрес компьютера на Android не является адресом телефона.

Скачайте JSON через «Резервная копия истории» на главной. Не очищайте хранилище браузера. Выход из аккаунта
скрывает закешированный банк/историю; данные сохраняются для повторного входа тем
же владельцем. Вход другим аккаунтом их не открывает и не перепривязывает.
После первого успешного входа доступна явная кнопка продолжения офлайн, если
ранее загруженные данные и разрешённый профиль есть на этом устройстве. Полный
перезапуск страницы без доступного сервера проверен в production PWA этапа 4.
После возвращения сети членство перепроверяется, очередь возобновляет отправку.

## Как воспроизвести настройку нового проекта

Публичные параметры — в `.env.local` по пустому `.env.example`. Secret/service_role
и пароль базы клиенту не нужны: загрузка банка выполняется от разрешённого
Auth-пользователя через ограниченный install_bank RPC и приватный Storage.

```sh
node scripts/prepare-cloud-setup.mjs
```

Генератор создаёт `private/setup-supabase.sql` из версионированных миграций.
Его выполняют в SQL Editor своего личного проекта. Вопросов, картинок и секретов
в нём нет. Скрипт атомарен, проверяет наличие схемы и допускает повторный запуск
без удаления данных. Автоматически включает владельца только когда нет членов
и существует ровно один Auth-пользователь. Если пользователей несколько,
скрипт останавливается: UUID владельца следует выбрать явно, а не произвольно.

Настройки Auth вне SQL: Dashboard → Authentication → Sign In / Providers:
Allow new users to sign up = off; Allow anonymous sign-ins = off;
Allow manual linking = off; Confirm email = on. `supabase/config.toml` — локальный
эталон соответствующих настроек, он не публикует параметры и не применяется
к облаку автоматически. Не отправлять нерассмотренные CLI defaults в готовый проект.

Проверка прав в настоящей базе: `supabase/tests/verify-live.sql`. Она только читает
метаданные и временно подставляет UUID не-члена в транзакции с ROLLBACK.
Проверка через publishable API без Auth: все 13 таблиц возвращают HTTP 401
с PostgreSQL 42501 (permission denied). Отчёт: `reports/cloud-api-check.json`.

## Архитектура и границы проверки

- IndexedDB v2 добавляет outbox, syncHeads и conflicts, сохраняя исходные таблицы v1.
  Завершённая попытка, позиция, очистка пропуска и события очереди — одна транзакция.
- attempts и attempt_annotations — append-only. Повторная отправка использует
  INSERT ON CONFLICT DO NOTHING; после неё проверяется идентичность существующего
  события. Совпавший UUID с другим содержимым даёт ошибку, а не перезапись.
- user_sync_state хранит version/event_id и снимки session/flag/preferences/active.
  save_sync_state — compare-and-swap; SESSION/SYNC_CONFLICT не решаются по времени.
  Состояние повторений пересчитывается из объединённых попыток/аннотаций.
- Старые study_sessions/user_question_flags/user_preferences из миграции 0001
  защищены, но транспорт v2 использует user_sync_state. question_images оставлена
  под нормализованные метаданные; действующая привязка PNG/UUID/SHA-256 —
  image_manifest внутри закрытой bank_source и соответствующие Storage paths.
- install_bank проверяет структуру, количество, ключи и порядок, создаёт FK-таблицы
  и сохраняет исходный JSON. Повтор идентичен либо отклонён; старый банк не меняется.
  Для изменения официальных ключей или версии банка нужен отдельный разбор.
- Ни позиции, ни повторы не являются источником счётчика охвата. Время попыток UTC;
  source_updated_at сохраняется исходной строкой, без придуманного часового пояса.

Проверки PostgreSQL/PGlite выполняют настоящие миграции на синтетических Auth/Storage
схемах. Браузерный cloud-client E2E использует настоящий SDK и два изолированных
браузерных хранилища, но **синтетический HTTP API**, не аккаунт владельца. Настоящая
схема, запрет anon и параметры проекта проверены отдельно. Первый реальный вход и синхронизация подтверждены владельцем; физическая
смена ОС ещё не проверена. [Офлайн и установка PWA](STAGE_4.md).
