# Постоянный HTTPS-адрес

Приложение работает как статическая PWA с личным Supabase, без серверного
Node.js и зависимости от Codex/ChatGPT во время учёбы.

## Подготовленная сборка

В корне проекта:

```sh
npm run package:site
```

Команда собирает приложение, проверяет отсутствие платного банка и секретных
ключей, создаёт `private/trainer-site.zip`. В ZIP лежит только содержимое `dist/`,
включая manifest, иконки, service worker и правила заголовков.
Не загружайте на хостинг корень проекта или исходный `platform_83_export.zip`.

`.env.local` нужен при сборке; его значения URL и publishable key попадут
в клиентскую сборку согласно модели Supabase. Сам файл туда не копируется.
После изменения этих параметров нужна новая сборка. Secret/service_role не нужен.

## Cloudflare Pages, ручная загрузка

Нужен личный аккаунт [Cloudflare Dashboard](https://dash.cloudflare.com/).
После регистрации и подтверждения email:

1. Откройте Workers & Pages → Create application → Pages / Get started →
   Drag and drop your files (названия могут отличаться в текущем Dashboard).
2. Укажите имя проекта и загрузите `private/trainer-site.zip`.
3. Нажмите Deploy site / Save and Deploy. Сохраните основной адрес `https://…pages.dev`.
   Свой домен не обязателен. Используйте этот основной адрес на всех устройствах.
4. Откройте сайт, войдите тем же аккаунтом тренажёра, подтвердите привязку
   нового браузера. Дождитесь загрузки банка/картинок и «Синхронизировано».
   Ранее перенесённая история загрузится из Supabase.
5. На главной проверьте «Установка и работа без сети»; установите приложение
   кнопкой или через меню браузера. Сделайте копию JSON.

Эти действия соответствуют [Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/).
Для такого проекта будущие обновления тоже загружаются вручную через Create a new
deployment → Production, сохраняя основной адрес и данные браузеров.
Переход на Git integration потребует другого проекта Cloudflare; для личного
тренажёра ручная загрузка позволяет разместить готовую сборку без репозитория.

`public/_headers` задаёт CSP и защитные заголовки, отключает HTTP-кеширование
index/sw, оставляет длительный кеш только хешированным ассетам. Pages применяет
их по [правилам заголовков](https://developers.cloudflare.com/pages/configuration/headers/).
На другом хостинге эти же правила нужно перенести в его конфигурацию:
Vite preview не моделирует применение `_headers`.

## Приёмка после размещения

1. Без входа в чистом браузере сайт показывает вход, а не банк вопросов.
2. Войдите, дождитесь загрузки 14/961 и синхронизации. Решите вопрос, обновите:
   попытка и позиция сохраняются.
3. На другом устройстве войдите тем же аккаунтом, выберите «Продолжить здесь».
   Проверьте историю и позицию. Повторите Windows → Android → Linux.
4. Включите авиарежим, полностью закройте приложение, запустите снова.
   Продолжите офлайн; откройте вопрос с картинкой, ответьте. Верните сеть:
   очередь отправляется, на другом устройстве появляется новая попытка.
5. Выйдите из аккаунта, отключите сеть и перезапустите. Банк/история закрыты,
   продолжение офлайн недоступно; после входа тем же владельцем данные возвращаются.
6. Загрузите следующую версию сайта. В прежней вкладке должно появиться
   «Обновить приложение» после проверки обновления (можно закрыть и открыть сайт).
   После обновления история/сессия сохранены; браузерная консоль не содержит
   CSP-ошибок. Проверьте заголовки `index.html` и `sw.js` в Network.

## GitHub Pages (текущий вариант)

Репозиторий: https://github.com/Velheon/1c-professional-trainer
Адрес: https://velheon.github.io/1c-professional-trainer/

Settings → Pages → Source: GitHub Actions. Workflow `.github/workflows/pages.yml`
собирает `dist` с `VITE_BASE_PATH=/1c-professional-trainer/`, выполняет проверки
и публикует только этот каталог. Для сборки задаются Repository variables
`VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` в Settings → Secrets and
variables → Actions → Variables. Это публичные параметры, не service_role.
Исходный архив, `.env.local`, отчёты и история в репозиторий не загружаются.

Для локальной проверки именно этой сборки:

```sh
VITE_BASE_PATH=/1c-professional-trainer/ npm run build
VITE_BASE_PATH=/1c-professional-trainer/ npm run preview
VITE_BASE_PATH=/1c-professional-trainer/ npm run test:e2e -- --project pwa
```

GitHub Pages не применяет Cloudflare `_headers`/`_redirects`. CSP включается
в HTML production-сборки; доступ к банку по-прежнему контролирует Supabase RLS.
Manifest использует относительные пути, service worker ограничен подпапкой сайта;
очистка кеша не затрагивает другие приложения на том же домене.
На новом адресе войдите тем же аккаунтом тренажёра и дождитесь синхронизации.

На размещённом сайте проверены HTTP 200, форма входа, доступность manifest/sw
и отсутствие карточек вопросов без авторизации; ошибок JavaScript не обнаружено.
